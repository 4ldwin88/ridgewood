# Drive Authority and Challenge Protocol

1. Identify the exact Drive rule governing the behavior.
2. Implement it as written when it is coherent and feasible.
3. Challenge it when implementation reveals contradiction, ambiguity, unsupported assumptions, security/maintainability risk, unnecessary complexity, or a materially simpler way to satisfy the same intent.
4. Do not encode a silent workaround.
5. Resolve the governing Drive source first.
6. Implement and test the resolved rule.

Technical notes in this repository may document implementation choices but cannot become a competing source of Ridgewood business truth.
